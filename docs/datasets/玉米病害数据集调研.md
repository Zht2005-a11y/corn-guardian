## 三、建议的目标类别（9 类）与数据来源

| # | 类别（中文）       | 英文键                          | 现有            | 主要来源                         | 备注                         |
| - | ------------ | ---------------------------- | ------------- | ---------------------------- | -------------------------- |
| 1 | 玉米大斑病        | `Blight`                     | ✅ 1 276 / 315 | MCDD + A2                    | 保留原键，不破坏已有接口               |
| 2 | 玉米小斑病        | `Southern_Leaf_Blight`       | ❌             | B1 / B2                      | 国内夏玉米区高发，只能靠申请/联系作者        |
| 3 | 玉米灰斑病        | `Gray_Leaf_Spot`             | ✅ 460 / 114   | MCDD + **A1** + A2 + A3 + A4 | 样本偏少，A1 可补一批               |
| 4 | 玉米普通锈病       | `Common_Rust`（P. sorghi）     | ✅ 1 045 / 261 | MCDD + A2                    | ⚠️ 别把 A1 的锈病并进来，见下方"坑"     |
| 5 | 玉米南方锈病       | `Southern_Rust`（P. polysora） | ❌             | **A1** + A2                  | 与普通锈病**极易混**，必须做混淆矩阵       |
| 6 | 玉米弯孢菌叶斑病     | `Curvularia_Leaf_Spot`       | ❌             | **A1** + B1/B2               | A1 有一般/严重两级                |
| 7 | 玉米褐斑病        | `Brown_Spot`                 | ❌             | A3 + B2                      |                            |
| 8 | 玉米花叶病毒病（矮花叶） | `Mosaic_Virus`               | ❌             | **A1** + B1                  | 症状是花叶/褪绿条纹，不是斑点，与其它类区分度反而高 |
| 9 | 健康叶片         | `Healthy`                    | ✅ 930 / 232   | MCDD + A1 + A2               |                            |



> **只用 A1（一个数据集）就能从 4 类扩到 7 类**：新增 南方锈病、弯孢菌叶斑病、花叶病毒病。小斑病、褐斑病要等 A3/B1/B2。  
> 圆斑病（B1 有）放第二批；瘤黑粉、纹枯、丝黑穗病理部位在穗/茎，不适合当前「叶片特写」采集方式。

### ⚠️ 一个必须注意的命名坑

A1 里的"玉米锈病"标注是 **`Puccinia polysora`，即南方锈病**；而我们现有 `Common_Rust` 是 **普通锈病（P. sorghi）**。两者孢子堆颜色（橙褐 vs 橘红）、着生叶面（叶背隆起 vs 双面）、发生温度都不同。**如果直接把 A1 的锈病图片标成 `Common_Rust`，等于把两种病混成一类**，模型学到的是一团模糊边界。正确做法：单独建 `Southern_Rust` 类，并在混淆矩阵里盯住这两个类的互错率。

## 五、风险与建议顺序

1. **类别越界**：`corn_smut`（瘤黑粉）和纹枯、丝黑穗主要在穗/茎，叶片特写里几乎没有典型症状。若强行加入，模型会靠背景/光照走捷径，指标虚高、现场不可用。**建议先做 7 类叶片病**，穗部病害另开一条"果穗/整株"链路。
2. **同源泄漏**：A3（Roboflow）、A4（CD\&S 增强图）、A5（PlantDoc）之间大量图片同源（文件名里能看到 `Corn_Common_Rust (21).jpg`、`___RS_GLSp-9352`）。合并前必须按 **md5 去重**，并且划分 train/test 时按"原始来源"分层，否则测试集分数会虚高。
3. **域差异**：A1/A5 有大量白底摆拍图，与现场手机拍摄差距大。建议训练时**按来源上采样田间图**，并在验证集里单独保留一个"纯田间"子集来评估。
4. **类别不均衡**：MCDD 里灰斑只有 574 张，新类若只有几百张，需要 class weight 或重采样（配置里已有 `class_weighted_loss` 开关）。
5. **严重度**：现有严重度靠 bbox 面积推算。A1（一般/严重）与 A4（1~5 级）都能提供监督信号，后续可以把严重度做成独立的第二个输出头，比现在准得多。

**推荐路径**

```
第 1 步（1~2 天，收益最大）：AI Studio 下 A1（CC0，国内直连），只取 label 9~16 玉米 8 类
                    → 与 MCDD 合并，得到 7 类：大斑/灰斑/普通锈/南方锈/弯孢菌叶斑/花叶病毒/健康
                    → 同时拿到"一般/严重"标签，可先把严重度改成模型输出
第 2 步（3~5 天）：加 A2（PLS） + A3（褐斑/霜霉） → 扩到 8~9 类，重训三模型
第 3 步（长期）   ：申请 B1（9 类中文数据集），补齐小斑/圆斑/矮花叶细分，形成国内最强 10 类
```

## 六、GitHub 上的玉米数据集：全是同一血统（已实测）

在 GitHub 上搜 `corn disease dataset` / `maize leaf disease dataset`，能拿到的仓库（`haberkornm/...`、`ai-agriculture-circuits-and-systems/corn_maize_leaf_disease`、`lonlonago/...`、`Dataenthusiast11/...`）**统统只有 4 类**，而且都是 Kaggle `smaranjitghose/corn-or-maize-leaf-disease-dataset`（4 188 张）或 PlantVillage 的转发。

**实测证据**（本地 MCDD vs 本地 PlantVillage，按 md5 逐张比对）：

| 类别             | MCDD（去重后） | PlantVillage 玉米 | 完全相同      |
| -------------- | --------- | --------------- | --------- |
| Blight         | 1 346     | 985             | **985**   |
| Common_Rust    | 1 306     | 1 192           | **1 192** |
| Gray_Leaf_Spot | 574       | 513             | **513**   |
| Healthy        | 1 162     | 1 162           | **1 162** |
| 合计             | 4 388     | 3 852           | **3 852** |

> PlantVillage 的 3 852 张玉米图，**100% 已经被 MCDD 包含**（`Corn_Health (196).jpg` 与 `6a570f29-...___R.S_HL 0617 copy.jpg` 是同一张）。所以本地这份 PlantVillage（38 类 / 54 304 张）**对玉米扩类零贡献**，不要再往里加数据。

### ⚠️ 顺带查出来的数据质量问题

| 项目                  | 数值                    |
| ------------------- | --------------------- |
| MCDD 图片总数           | 4 633                 |
| 唯一图片（去重后）           | 4 386 → 有 **244 组重复** |
| train 内部重复          | 178 组                 |
| test 内部重复           | 7 组                   |
| **跨 train/test 泄漏** | **59 组，占测试集 6.4%**    |

也就是说现在报告的 `val_acc 99.1%` **有虚高**——测试集里有 6.4% 的图片在训练集里出现过（例：`train/Blight/02eee796-...RS_NLB 3546.JPG` 与 `test/Blight/Corn_Blight (160).JPG` 是同一张）。扩类之前应该先去掉这个泄漏，否则新类的指标同样不可信。
