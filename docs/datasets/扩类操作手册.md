## 三、命令序列

在 `model/corn_disease_system_20261021/` 目录下执行：

```bat
:: 1. 拆分玉米 8 个 label（非玉米自动跳过）
python scripts\split_aic2018.py ^
  --ann    D:\shijianzhou\corn-guardian\dataset\AIC2018_raw\AgriculturalDisease_trainingset\AgriculturalDisease_train_annotations.json ^
  --images D:\shijianzhou\corn-guardian\dataset\AIC2018_raw\AgriculturalDisease_trainingset\images ^
  --out    D:\shijianzhou\corn-guardian\dataset\AIC2018\data\train

:: 2. 先干跑，确认每类数量与去重结果（不写文件）
python scripts\prepare_multiclass.py --plan scripts\dataset_plan.example.json --dry-run

:: 3. 确认无误后落盘
python scripts\prepare_multiclass.py --plan scripts\dataset_plan.example.json
```

第 2 步会打印类似：

```
[MCDD]   4633 张  {'Blight': 1591, 'Common_Rust': 1306, 'Gray_Leaf_Spot': 574, 'Healthy': 1162}
[AIC2018] xxxx 张 {'Southern_Rust': ..., 'Curvularia_Leaf_Spot': ..., ...}
扫描到 N 张，唯一图片 M 张，去掉重复 K 张
Blight                 共  xxxx  train  xxxx  test  xxx
...
复检通过：train / val / test 之间零重叠
```

**重点看三行**：
- `去掉重复 K 张` —— 跨数据集同源图片会被合并（PlantVillage 血统的图会大量命中）
- 各新类别的数量 —— 少于 100 张会告警，需要补数据或靠 class weight
- `复检通过：train / val / test 之间零重叠`

## 五、已经替你处理掉的坑

| 坑 | 说明 |
|---|---|
| **`Southern_Rust` 被静默归成 `Common_Rust`** | `dataset.py` 的类别名归一化里，模糊匹配中的别名 `"rust"` 会把 `southern_rust` 吞掉（实测 14 张南方锈被算进普通锈）。已在 `src/config.py` 加入「精确匹配标准键优先」+ 南方锈/弯孢/花叶的别名。 |
| MCDD 内部 244 组重复、59 组跨 train/test（占测试集 6.4%） | `prepare_multiclass.py` 全局按 md5 去重并重新分层划分，新数据集不存在此问题。 |
| 同一张图被标成不同病种 | 默认 `conflict_policy: skip` —— 整组丢弃，不污染新类别；实测 MCDD 内部就有 2 组（大斑 vs 灰斑）真实标注冲突。 |
| 新类会被门控拒识 | 门控类中心按 `model::class` 存储，扩类后必须重建（见上）。 |
| 样本按钮写「南方锈病」、诊断卡写「普通锈病」 | 样本接口原来用硬编码显示名，已改为统一取知识库 `name_cn`。 |
| 新病种没有处方 | 知识库已补 `Southern_Rust` / `Curvularia_Leaf_Spot` / `Mosaic_Virus` 三条完整条目（症状 / 发生规律 / 结构化处方 / 防治要点），并支持按严重度四档动态生成。 |

## 六、类别顺序（不要随意改）

```json
["Blight", "Common_Rust", "Gray_Leaf_Spot", "Healthy",
 "Southern_Rust", "Curvularia_Leaf_Spot", "Mosaic_Virus"]
```

前 4 个索引与现有 4 类模型完全一致，方便复用已有权重做增量微调；新类追加在后面。

**这个顺序必须同时满足三处一致**：`configs/config.7cls.yaml` 的 `data.class_names`、`scripts/dataset_plan.example.json` 的 `class_order`、以及合并输出目录的文件夹名。

## 七、如果 AI Challenger 里某一类太少

AI Challenger 的玉米是「按严重度拆」的，一般/严重各一类。若某类样本偏少，可以：

1. 在 `dataset_plan.example.json` 里把 `10` 和 `11` 都映射到 `Gray_Leaf_Spot`（已经这么配了），等价于合并两级
2. 仍不够就补 figshare 的 *Diseases of maize in the field*（CC BY 4.0，含南方锈 SR 与 PLS），按同样方式加一个 source
3. 最后手段是 class weight（`config.7cls.yaml` 已开 `class_weighted_loss: true`）或 `--balance-sampler`
